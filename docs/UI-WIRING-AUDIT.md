# UI wiring and logic audit — 22 October 2026

Historical snapshot before the live provider connection and consolidation into one application. For current behavior, fixes, verification and unfinished work, see [Full application audit — 23 October 2026](FULL-AUDIT-2026-10-23.md). Statements below about separate Preview/Diary interfaces describe that earlier stage.

## Result

The local preview's daily workflows are functional, with the defects below corrected. The app is **not yet a fully connected production diary**: `/preview` is an isolated sample workspace, while `/diary` uses separate protected API-backed screens. The two interfaces still need consolidation/parity before release. No commits, pushes, deployment, cloud setup, real drive scan or production data changes were made.

## Corrections in this audit

| Defect                                                                                                                                 | Correction                                                                                                                                                                                                                                                                                                            |
| -------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Shared Search ignored the current screen's registered handler. Glance's local search and Stats' history focus action were unreachable. | Header delegates to the page handler where one exists; Home retains its inline library/online search. Expanded state follows the correct control.                                                                                                                                                                     |
| Library links ignored query/category/favorites and the private Library ignored incoming filters.                                       | Shared query interpretation applies supported deep links; preview also reads tag, availability and sort. Category links carry their category. Independent local filters survive category changes.                                                                                                                     |
| Clear filters left linked query/category/favorites behind.                                                                             | Clears every supported filter parameter while retaining Trash/map layout state.                                                                                                                                                                                                                                       |
| Files captured its incoming disk only at component creation.                                                                           | Incoming disk changes are observed when the same route is reused.                                                                                                                                                                                                                                                     |
| Spoiler preference reverted after reopening.                                                                                           | Preference is saved separately in IndexedDB; unavailable storage is reported. Control is disabled until initialization completes.                                                                                                                                                                                     |
| Two preview tabs could silently overwrite each other's notes/history/Queue.                                                            | Atomic revision comparison inside the IndexedDB write transaction rejects stale saves. The controller reloads the latest state, clears invalid Undo, surfaces the conflict and allows an explicit retry. Tab focus refreshes newer saved snapshots. This is conflict protection, not automatic cloud sync or merging. |
| Success/Undo could appear before a save completed.                                                                                     | Success feedback and Undo are installed after the storage operation resolves. Storage failure is explicitly session-only; conflict is not reported as success. Add/bulk dialogs retain actionable error feedback.                                                                                                     |
| A failed initial read could allow fallback sample data to overwrite an incompatible saved workspace.                                   | Such sessions cannot write the workspace back to device storage. The original saved record remains intact.                                                                                                                                                                                                            |
| Individual preview episode controls could record future/undated episodes even though Up Next/slider excluded them.                     | A shared valid-air-date predicate gates current preview controls and controller writes. Archived titles cannot accept new domain watch records. Existing watched episodes can still be unwatched. Historical import policy is separate.                                                                               |
| An invalid Explore year could leave its loading flag active after cancellation.                                                        | Invalid input cancels pending discovery and clears the loading state.                                                                                                                                                                                                                                                 |
| Private Library treated `trash=0` as Trash.                                                                                            | Trash requires the explicit `trash=1`, matching its API.                                                                                                                                                                                                                                                              |

The cross-tab protection is compatible with existing unversioned local preview records; no reset or migration of the user's sample workspace is required. Preview writes still persist a whole sample snapshot. Large real libraries must use the existing granular API model rather than extending this sample-store approach.
